## AAS 모델 파일 이해하기

FA³ST Service가 읽는 모델 파일의 구조와 작성 방법을 설명합니다. 모델 파일은 AAS v3 환경(Environment) JSON입니다. 이 절의 모델은 센서마다 쉘 하나와 서브모델 하나를 두고, 의미 정의(ConceptDescription) 3개를 함께 담습니다. 아래는 센서 `sensor01` 부분을 발췌한 예입니다.

```json
{ "assetAdministrationShells": [ {
    "modelType": "AssetAdministrationShell", "id": "urn:kadap:edu:aas:sensor01", "idShort": "Sensor_sensor01",
    "assetInformation": { "assetKind": "Instance", "globalAssetId": "urn:kadap:edu:asset:sensor:sensor01" },
    "submodels": [ { "type": "ModelReference", "keys": [ { "type": "Submodel", "value": "urn:kadap:edu:sm:temphumidity:sensor01" } ] } ] } ],
  "submodels": [ { "modelType": "Submodel", "kind": "Instance", "id": "urn:kadap:edu:sm:temphumidity:sensor01", "idShort": "TempHumidity_sensor01",
    "semanticId": { "type": "ExternalReference", "keys": [ { "type": "GlobalReference", "value": "urn:kadap:edu:semantic:TempHumidity:1.0" } ] },
    "submodelElements": [
      { "modelType": "Property", "idShort": "Temperature", "valueType": "xs:double", "value": "0.0",
        "semanticId": { "type": "ExternalReference", "keys": [ { "type": "GlobalReference", "value": "urn:kadap:edu:semantic:Temperature:1.0" } ] } },
      { "modelType": "Property", "idShort": "Humidity", "valueType": "xs:double", "value": "0.0",
        "semanticId": { "type": "ExternalReference", "keys": [ { "type": "GlobalReference", "value": "urn:kadap:edu:semantic:Humidity:1.0" } ] } },
      { "modelType": "Property", "idShort": "SensorId", "valueType": "xs:string", "value": "sensor01",
        "semanticId": { "type": "ExternalReference", "keys": [ { "type": "GlobalReference", "value": "urn:kadap:edu:semantic:SensorId:1.0" } ] } } ] } ],
  "conceptDescriptions": [ { "modelType": "ConceptDescription", "id": "urn:kadap:edu:semantic:Temperature:1.0", "idShort": "Temperature", "embeddedDataSpecifications": [ … ] },
    { "id": "urn:kadap:edu:semantic:Humidity:1.0", … }, { "id": "urn:kadap:edu:semantic:SensorId:1.0", … } ] }
```

### 구성

| 항목 | 설명 |
|---|---|
| `assetAdministrationShells[]` | 쉘입니다. `id`, `idShort`, 자산 정보 `assetInformation`, 서브모델 참조 `submodels`로 이루어집니다. |
| `submodels[]` | 서브모델입니다. `id`, `idShort`, `kind`, `semanticId`, `submodelElements[]`로 이루어집니다. |
| `submodelElements[]` | 프로퍼티입니다. `modelType`이 Property이며, `idShort`, `valueType`, `value`, `semanticId`로 이루어집니다. |
| `conceptDescriptions[]` | IEC 61360 형식의 의미 정의입니다. `Temperature`, `Humidity`, `SensorId` 3개를 담으며, 각 ID는 프로퍼티의 `semanticId`와 같은 `urn:kadap:edu:semantic:<이름>:1.0`입니다. |

### 모델 파일 작성하기

실행 키트에서는 `gen.mjs`가, 장치에서는 faaast 모듈이 기동할 때 모델 파일을 자동으로 만듭니다. 모델 파일을 직접 작성하려면 다음 순서대로 진행하세요.

1. 센서마다 쉘 ID는 `urn:kadap:edu:aas:<센서 ID>`, 서브모델 ID는 `urn:kadap:edu:sm:temphumidity:<센서 ID>`로 정해 쉘과 서브모델을 작성하세요.
2. 숫자 프로퍼티는 `valueType`을 `xs:double` 또는 `xs:int`로 지정하세요. `xs:string`으로 지정하면 값이 문자열로 표시됩니다.
3. FA³ST를 실행한 뒤 `/api/v3.0/submodels/<서브모델 ID의 base64url>`을 열어, 모델 파일의 서브모델이 그대로 표시되는지 확인하세요.

모델 파일에 쓰는 주요 속성은 다음과 같습니다.

| 항목 | 설명 | 예 |
|---|---|---|
| `id` | 환경 전체에서 유일한 IRI 또는 URN입니다. | `urn:kadap:edu:aas:sensor01` |
| `idShort` | 사람이 읽기 쉬운 짧은 이름입니다. 같은 상위 요소 안에서는 중복될 수 없습니다. | `Sensor_sensor01`, `TempHumidity_sensor01` |
| `semanticId` | 서브모델 템플릿을 가리키는 시맨틱 ID입니다. Catena-X PCF 같은 표준 템플릿을 쓸 때는 그 템플릿에 정해진 값을 씁니다. | `urn:kadap:edu:semantic:TempHumidity:1.0` |
| 프로퍼티 | `idShort`, `valueType`, 초기값을 지정합니다. | `Temperature`(xs:double, 0.0), `Humidity`(xs:double, 0.0), `SensorId`(xs:string, 센서 ID) |

> **참고 -** FA³ST는 AAS v3 형식의 모델만 읽을 수 있습니다. `id`나 `idShort`가 중복되면 시작하지 않습니다.
